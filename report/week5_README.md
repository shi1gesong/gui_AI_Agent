## 三、方法

### 3.1 模型选择：Qwen2-VL-2B-Instruct + LoRA

| 考虑 | 结论 |
|---|---|
| 显存 | 本机 RTX 5070 Ti 16GB。2B 模型 bf16 约 4.5GB，加梯度检查点后 LoRA 训练可直接跑；3B（Qwen2.5-VL）也支持，显存紧张时 `--load-4bit` 走 QLoRA |
| 大纲推荐 | Qwen-VL 系列。Qwen2-VL 是 Qwen-VL-Chat 的后继，transformers 原生支持，坐标定位能力更好 |
| 数据量 | 训练集只有 808 条，模型越大越容易过拟合；2B + LoRA 比较匹配 |

LoRA 只挂在语言模型的 7 种线性层（q/k/v/o/gate/up/down）上，**视觉编码器冻结**。Qwen2.5-VL 的视觉 MLP 也叫 gate_proj/up_proj/down_proj，所以用正则 `^(?!.*visual).*\.(q_proj|…|down_proj)$` 排除视觉分支（有测试覆盖）。默认 r=16、alpha=32、dropout=0.05、学习率 2e-4、3 个 epoch、等效批大小 8、线性预热 + 余弦退火。

### 3.2 数据集

来源是第3周解析的 ScreenAgent 标注（每条 = 一张 1024×768 截图 + 总任务 + 子任务 + 标注动作序列）。

| 集合 | 样本 | 会话 | 用途 |
|---|---|---|---|
| train | 808 | 183 | 训练 |
| val | 82 | 20 | 选最佳 epoch（验证损失最低） |
| test | 282 | 70 | ScreenAgent 官方测试划分，只用于最终对比 |

- **按会话划分验证集**：同一会话的截图几乎一样，按条随机划分会让验证集虚高。三个集合之间会话重叠为 0（`report/week5_assets/dataset_stats.json`）。
- 首个动作分布（测试集）：click 178、type 36、key 25、double_click 14、scroll 12、right_click 8、move 5、drag 3、wait 1。约 19% 的样本需要输出多个动作（如“点击搜索框 → 输入 → 回车”）。
- 丢弃 1 条没有可执行动作的样本，没有重复样本。

### 3.3 输出格式

模型输出一个 JSON 数组，坐标是相对截图宽高的千分比（0~1000），与分辨率无关：

```json
[{"action": "click", "x": 120, "y": 45}, {"action": "type", "text": "天气"}, {"action": "key", "keys": ["enter"]}]
```

动作 9 种：click / double_click / right_click / move / drag / scroll / type / key / wait。训练时只对回答部分计算损失（提示词部分 label = -100），训练前缀与推理时 `add_generation_prompt=True` 的输入逐 token 一致（有测试验证）。

解析器（`finetune/action_format.py`）对模型输出很宽容：代码块、`<think>` 标签、单个对象、`action_type` 别名、`point`/bbox/Qwen 的 `<|box_start|>(x,y)` 坐标、0~1 小数、像素坐标都能转换。这样基座模型零样本时“格式不对但意思对”的输出也能被公平地打分。

### 3.4 提示词工程

| 版本 | 内容 |
|---|---|
| v0_minimal | 只给任务，要求输出 JSON 动作（接近第3周写法，作为基线） |
| v1_schema | 说明坐标约定、9 种动作及字段、“只输出 JSON 数组” |
| v2_fewshot | v1 + 3 个与截图无关的文字示例（点击 / 输入+回车 / 组合键） |

LoRA 用 v1_schema 训练和推理。基座模型三种都测，回答两个问题：只改提示词能提升多少？微调又能再提升多少？

### 3.5 评测指标

| 指标 | 含义 |
|---|---|
| 格式合格率 | 输出能解析出至少一个合法动作 |
| 动作类型准确率 | 第一个动作类型正确 |
| 首动作正确率 | 第一个动作类型和参数都正确（坐标 ≤ 50px、文字一致、按键一致、滚动方向一致） |
| 整步成功率 | 动作数相同且每个动作都正确 |
| 点击命中 @25/50/100px | 坐标与标注的距离（按 1024×768 原图换算） |
| 输入文字 / 按键准确率 | 标注含输入或按键动作的样本中，内容一致的比例 |

### 3.6 接入 Agent：`--act vlm`

```
Windows（gui-agent-win）                           WSL2（gui-agent，GPU）
 GUIAgent ── 规则能处理的子任务（打开程序/组合键/等待）直接执行
    │ 需要看屏幕的子任务
    ▼
 截图 → 缩到长边 1280 的 JPEG → POST /act ───────►  finetune/serve.py：Qwen2-VL + LoRA
                                                        │
 0~1000 坐标 × 逻辑屏幕尺寸 = 鼠标坐标 ◄── JSON 动作 ──┘
    ▼
 ControllerExecutor（动作带 point 时跳过 OCR 匹配，直接点击）
```

WSL2 监听 0.0.0.0:8765，Windows 通过 localhost:8765 访问（WSL2 默认转发）。坐标是归一化的，换算时用鼠标逻辑尺寸，所以 DPI 缩放 100%~200% 都能点准（有测试覆盖）。

## 五、问题排查记录

| 问题现象 | 原因 | 解决方案 |
|---|---|---|
| 模型输出 `{"action": "key", "keys": ["enter"]}` 被解析成空 | 解析器先找 `[`，取到了对象里面的 `["enter"]` | 看 `[` 和 `{` 谁先出现，决定按数组还是对象解析 |
| 使用 v2_fewshot 提示词时报 `KeyError: '"action"'` | 示例里的 JSON 花括号被 `str.format` 当成占位符 | 示例文字中的花括号转义 |
| `evaluate --max-pixels 12544` 报 min_pixels > max_pixels | 只调小了上限，下限仍是默认值 200704 | 未指定下限时取 min(默认下限, 上限)；新增 `--min-pixels` |
| 本机 `pytest -m gpu` 9 个用例 setup 报 `cv2.__spec__ is None` | WSL 环境没有 opencv 时，测试配置放进 sys.modules 的 cv2 替身没有 `__spec__`，transformers 导入时调用 find_spec 报错（云端装了 opencv，没暴露） | 替身补上 `__spec__`；在云端模拟无 opencv 环境复现并验证修复 |
| 本机运行脚本报 `pipefail: invalid option`、找不到 C 编译器、连不上 hf-mirror、训练进度不显示 | Windows checkout 转 CRLF；新版 peft 顺带导入 bitsandbytes；镜像只适合国内；Python 经管道整块缓冲 | `.gitattributes` 强制 LF；脚本自动处理 bitsandbytes；默认直连 HF；`PYTHONUNBUFFERED=1` |
| 微型模型用 LoRA 记不住整句目标 | 隐藏维只有 64，LoRA 容量太小（与真实 2B 模型无关） | “能逐字生成”这个端到端用例改用全参数训练微型模型；LoRA 用例只验证损失下降、挂载位置、保存/加载一致 |

前 3 个缺陷由新写的测试用例发现；cv2 替身缺陷由本机 GPU 用例发现。

## 六、已知局限

1. **领域差异**：ScreenAgent 是 1024×768 的 Linux/Windows 混合桌面，本机是 2560×1440 Windows 11。归一化坐标能解决分辨率问题，界面风格的差异要看真机效果。
2. **截图保真度**：2560×1440 截图会被缩到 max_pixels（约 80 万像素）以内，小图标可能看不清；可以调大 `--max-pixels`，代价是速度和显存。
3. **数据量**：808 条训练样本偏少。如果效果不理想，下一步可以用第4周的模拟桌面和真机轨迹自动生成本项目领域的训练数据。
4. few-shot 变差的原因目前是推测（见对比报告 2.1），需要看逐条输出确认。
