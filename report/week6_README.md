## 三、方法

### 3.1 复杂任务分解（`agent/decomposer.py`）

```
指令 ──► 屏蔽引号内文字 ──► 分句（编号 / 然后、接着、最后… / 逗号） ──► 每句：模板匹配 → 第4周规则规划器 → LLM 兜底
                                                                               │
                                                     上下文：当前程序、已打开文件、刚输入的文字
                                                                               ▼
                                          TaskGraph = [Goal(子任务列表, 完成检查, 能否整体重做), …]
```

- **引号保护**：“输入‘你好，然后再见’”里的逗号和“然后”不会被拆开。
- **连接词后必须是动作**：“然后给李四发送消息”会拆，“发送消息：然后见”不会拆。逗号只在每一段都以动作开头时才拆。
- **上下文继承**：“打开文件 a.txt，然后输入…，然后保存”中“输入”“保存”默认作用于记事本，“保存”的完成检查是“a.txt 里包含刚才输入的内容”。“打开计算器，然后给张三发消息，最后关闭计算器”中第二次用到已打开的程序时生成“切换到…”而不是重新打开。
- **不可重放目标**：发送消息标记为不可重放，后置条件不通过时不会整体重做，避免重复发送。

示例（`python -m agent.cli --no-llm --plan-only "打开计算器，然后给张三发送消息：明天上午10点开会，最后关闭计算器"`）：

```
[规划] 来源=template:open_app+send_message+close_app，3 个目标
  G1 打开计算器
     1. 打开计算器
     2. 等待2秒
     ✔ 完成检查：存在标题含 ['计算器', 'Calculator'] 的窗口
  G2 给张三发送消息：明天上午10点开会（不可重放）
     3. 打开模拟聊天
     4. 等待2秒
     5. 点击联系人“张三”
     6. 在“消息内容”框中输入“明天上午10点开会”
     7. 点击“发送”
     8. 等待1秒
     ✔ 完成检查：屏幕上出现「张三：明天上午10点开会」
  G3 关闭计算器
     9. 关闭计算器
     10. 等待1秒
     ✔ 完成检查：不存在标题含 ['计算器', 'Calculator'] 的窗口
```

### 3.2 错误检测与自动重试（`agent/recovery.py`、`agent/verifier.py`）

每个子任务的执行流程：

```
检查前台窗口（有新弹窗 → 关闭；目标程序不在前台 → 重新激活）
  → 截图 → 感知 → 决策 → 执行 → 截图 → 效果校验
  → 失败：错误分类 → 恢复动作 → 按类退避 → 重试（每类次数上限 + 总上限 6）
目标的子任务都完成 → 检查后置条件 → 不通过且可重放 → 整体重做一次
```

| 错误类 | 判断依据 | 最多尝试 | 恢复动作（下一次尝试前） |
|---|---|---|---|
| target_not_found | 屏幕上找不到目标文字 | 4 | 关新弹窗 → 激活目标程序 → 退避等待；第 3 次起放大截图再识别 |
| no_effect | 点击/输入后画面没有变化 | 2 | 关新弹窗 → 激活目标程序 → 退避 |
| popup | 出现本次运行之后新开的通知类窗口 | 3 | 关闭弹窗（失败则按 Esc）→ 激活目标程序，立即重试 |
| window_lost | 前台窗口不是目标程序（焦点被抢） | 3 | 关新弹窗 → 激活目标程序，立即重试 |
| perception | 截图/识别抛异常 | 3 | 退避后重拍 |
| app_launch | 打开程序后没看到窗口 | 2 | 先等最多 8 秒迟到窗口，确认没有再启动 |
| service | LLM/VLM 服务不可用 | 2 | 熔断后改用规则决策 |
| postcondition | 目标完成检查不通过 | 2 | 关新弹窗 → 激活 → 退避；可重放目标整体重做 |
| execution / unknown | 其他执行异常 | 2 | 退避 |
| invalid_action | 动作参数非法（规则模式下不重试） | 2 | 无 |
| abort | 用户中止（鼠标甩到角落 / Ctrl+C） | 1 | 立即停止全部任务 |

退避时间 0.5、1、2、4 秒；一个子任务所有类别加起来最多尝试 6 次；整个任务可用 `--budget` 设总时长上限。

**效果校验**：前后两帧缩到 320×180，RGB 任一通道差值超过 12 的像素至少 4 个才算“有变化”，同时给出变化区域。只有点击、双击、输入、拖拽要求必须有变化；快捷键、滚动、等待、打开/关闭程序不强制（它们的效果由后置条件检查）。阈值能过滤抗锯齿和压缩噪声（全屏亮度差 5 判定为无变化），同时能检测到 4K 截图上 1/40 屏宽的变化。

**弹窗处理的安全边界**：只关闭“本次运行开始之后才出现、且标题像通知/提示/警告/更新”的窗口，用户自己原来开着的窗口一律不动。

### 3.3 感知优化（`perception/perceiver_v2.py`、`perception/ui_detector.py`）

| 优化 | 做法 | 效果 |
|---|---|---|
| 只识别前台窗口 | 根据窗口位置裁剪截图，坐标再换算回屏幕 | Xvfb 1920×1080、窗口 900×600：EasyOCR 5.20 秒 → 1.52 秒 |
| 帧缓存 | 截图 MD5 → 识别结果（最近 8 帧） | 画面不变时 0.04 秒；后置条件检查、重试时大量命中 |
| 增量识别 | 只重新识别变化的格子（并扩展到相交的旧元素，避免切出半个按钮），每 5 次增量做一次全量 | 输入文字、选中联系人这类局部变化只识别一小块 |
| 碎片合并 | 同一行、间距很小的文字片段合并（“发”“送” → “发送”） | 减少找不到目标 |
| 词表纠错 | 3 个字以上、只差 1 个字的识别结果纠正为界面常用词或本次任务的目标词 | “消息内谷” → “消息内容” |
| 控件检测 | OpenCV 边缘 + 轮廓找输入框/按钮，把“消息内容”这类标签关联到右侧/下方的输入框 | 输入动作点击输入框中心而不是标签文字 |
| 重试时图像预处理 | 第 3 次找不到目标时把截图放大 2 倍再识别 | 小字号文字 |

### 3.4 实时监控与日志（`agent/monitor.py`）

每次运行的目录下：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 每个事件一行：计划、目标开始/结束、子任务开始/结束、每次尝试、重试、恢复、后置条件、降级、卡住 |
| `agent.log` | 人能读的日志（按大小轮转） |
| `status.json` | 当前状态（原子写入，读的时候不会读到半个文件）：状态机、进度、当前子任务、计数、ETA、心跳 |
| `metrics.json` | 各阶段（规划/感知/决策/执行/校验/反思）耗时的次数、均值、p50、p95、最大值 |
| `trace.json` | 完整轨迹（第4周格式 + 鲁棒性统计 + 感知统计） |

看门狗线程每 5 秒检查一次，某个子任务超过 60 秒没有进展会记录“卡住”事件。另开一个窗口运行 `python -m agent.monitor` 可以实时查看：

```

已用：0.4 秒
计数：重试 0  恢复 2  错误 0  降级 0  子任务成功 11 / 失败 0
  ✓ G1 给张三发送消息：明天上午10点开会（6 步）
  ✓ G2 给李四发送消息：收到请回复（5 步）
阶段平均耗时：plan 0.00s  perceive 0.02s  decide 0.01s  execute 0.00s  verify 0.03s  reflect 0.00s
```

（上例来自模拟桌面 + popup_on_select 故障：两次“恢复”就是关闭弹窗和重新激活聊天窗口。）

| 问题 | 原因 | 解决 |
|---|---|---|

## 六、已知局限

1. OCR 错两个字以上的短词无法通过文字匹配恢复。
2. 纯图标按钮仍需要第5周的视觉模型（`--act vlm`，v2 同样支持）；v2 还不会在 OCR 找不到时自动切到 VLM。
3. 目标找不到时最多尝试 4 次（退避共 3.5 秒，加上感知时间），更久的慢加载会失败（可以加 `--budget`，但每类重试次数没有开放到命令行）。
4. 弹窗、焦点相关的恢复在模拟桌面和 Xvfb 上验证过，Windows 真机还需要本机运行 C5/C6 确认。
5. 每个目标结束时多一次完成检查，无故障时平均多 0.4 秒。
